## 📌 What This Project Does

VIDS combines **Machine Learning**, **Zero-Knowledge Proofs (ZKP)**, and **Blockchain** to detect cyberattacks on network traffic — privately and verifiably.

Traditional IDS systems have two fatal problems:
- They expose sensitive network logs when sharing results
- Their ML models are black boxes with no cryptographic proof of correctness

This system solves both by:
1. **Detecting** attacks using a PyTorch neural network trained on NSL-KDD data
2. **Proving** the classification was correct using EZKL zero-knowledge proofs — without revealing the raw input
3. **Verifying** the proof publicly on the Ethereum Sepolia blockchain via a Solidity smart contract

## 🏗️ System Architecture (5 Layers)

```
Layer 5 — Frontend      →  Flask + HTML/CSS/JS dashboard (ngrok tunnel)
Layer 4 — Blockchain    →  Verifier.sol on Ethereum Sepolia testnet
Layer 3 — ZK Engine     →  EZKL v10.0.2 (ONNX → circuit → proof)
Layer 2 — ML Model      →  PyTorch MLP (full 41-feat + small 5-feat)
Layer 1 — Data          →  NSL-KDD dataset (125,973 training samples)
```

### Two Models

| | Full Model | Small Model |
|---|---|---|
| **Class** | IntrusionDetector | SmallDetector |
| **Input** | 41 features | 5 features |
| **Architecture** | Linear(41→64) → ReLU → Linear(64→32) → ReLU → Linear(32→1) → Sigmoid | Linear(5→10) → ReLU → Linear(10→1) → Sigmoid |
| **Parameters** | ~2,500 | ~80 |
| **Purpose** | Off-chain high-accuracy inference | On-chain ZK-friendly verification |
| **Gas Cost** | ~2.24M (impractical) | ~487K (viable) |
| **Accuracy** | ~78.66% | ~75–82% (varies per session) |

## 🚀 How to Run — Step by Step

> **This project runs entirely on Google Colab.** Do NOT try to run it locally on macOS — EZKL compiles OS-specific binaries and the compiled circuit will not work across platforms.

### Prerequisites

Before starting, you need:
- A **Google Account** (for Colab + Google Drive)
- **Google Drive** with at least 500 MB free (for the 100 MB KZG SRS file + model files)
- **ngrok account** (free) at [ngrok.com](https://ngrok.com) — get your auth token
- The **NSL-KDD dataset** files: `KDDTrain+.txt` and `KDDTest+.txt`

---

### Step 1 — Upload Dataset to Colab

1. Open [Google Colab](https://colab.research.google.com)
2. Create a new notebook
3. In the left sidebar, click the **Files** icon (folder icon)
4. Click **Upload** and upload both:
   - `KDDTrain+.txt`
   - `KDDTest+.txt`
5. These will be placed in `/content/` automatically

---

### Step 2 — Run Cell 1 (Data + Training + ONNX)

Copy and run **Cell 1** code. This will:

- Install required packages: `onnx`, `ezkl`
- Load NSL-KDD dataset from `/content/`
- Preprocess: encode categoricals, standardise features, binary labels
- Train the **IntrusionDetector** (41-feat MLP) for 10 epochs
- Print accuracy (expect ~78%)
- Save: `intrusion_model.pth`, `scaler.pkl`, `intrusion_model.onnx`, `input.json`

**Expected output:**
```
✅ Phase 1 done!
🚀 Training...
Epoch 1/10 done
...
Epoch 10/10 done
✅ Phase 2 done! Accuracy: 78.66%
✅ Phase 2b done!
```

---

### Step 3 — Run Cell 2 (EZKL ZK Proof Pipeline)

Copy and run **Cell 2** code. This will:

- Install `ezkl==10.0.2` and `solc` (Solidity compiler)
- Mount your Google Drive
- **Check Drive for cached SRS** — if not found, generates `kzg17.srs` (takes ~10 minutes the first time, seconds every time after)
- Run the full EZKL pipeline:
  - `gen_settings` → `calibrate_settings` → `compile_circuit` → `setup` → `gen_witness` → `prove` → `create_evm_verifier` → `verify`
- Save all generated files to Drive at `/MyDrive/zkml_project/`

**Expected output:**
```
✅ Loading SRS from Drive...   (or ⬇️ Generating SRS if first time)
✅ SRS ready!
✅ Proof verified: True
✅ All saved to Drive!
```

> ⚠️ **If you see "Generating SRS":** This takes approximately 10 minutes. Do not interrupt the cell. Once done, it saves to Drive — all future runs take seconds.

> ⚠️ **If you get a memory error:** Go to Runtime → Change runtime type → Select High-RAM. Colab free tier may not have enough RAM for the full model circuit.

---

### Step 4 — Run Cell 3 (Flask App + ngrok)

Before running, **replace the ngrok token** in the last section:

```python

ngrok.set_auth_token("YOUR_NGROK_TOKEN_HERE")
```

Get your token from [dashboard.ngrok.com](https://dashboard.ngrok.com/get-started/your-authtoken)

Then run **Cell 3**. This will:

- Install `pyngrok` and `flask`
- Load the full model from `intrusion_model.pth`
- **Train the small model** (SmallDetector, 5 features) on-the-fly — takes ~30 seconds
- Generate ZK proof for the small model (if `proof_5.json` doesn't exist)
- Start Flask server on port 5008 in a background thread
- Create ngrok tunnel and print the public URL

**Expected output:**
```
✅ Full model loaded
🔄 Building small model from training data...
✅ Small model trained & saved — accuracy: XX.XX%
🔏 Generating small model ZK proof (this takes a minute)...
```

## 🔗 Deploying to Remix IDE (Real On-Chain Verification)

To actually verify the proof on Ethereum Sepolia (not just simulate):

1. Get SepoliaETH from a faucet: [sepoliafaucet.com](https://sepoliafaucet.com)
2. Connect MetaMask to Sepolia network
3. Go to [remix.ethereum.org](https://remix.ethereum.org)
4. Create a new file → paste the contents of `Verifier_5.sol`
5. Compile with **Solidity 0.8.20**, enable optimizer
6. Deploy → select **Injected Provider (MetaMask)** → choose Sepolia → Deploy
7. After deployment, call `verifyProof()` with the calldata from the dashboard
8. Result `true` = ZK proof verified on-chain ✅

## ⚠️ Known Issues & Debugging

| Issue | Cause | Fix |
|---|---|---|
| `EZKL circuit compile error` | ONNX opset too high | Ensure `opset_version=10` in torch.onnx.export |
| `network.compiled execution error` | Built on wrong OS | Must compile and run on same Linux instance (Colab) |
| `EVM verification fails in Remix JS VM` | Stack depth limit | Use Python `ezkl.verify()` first; deploy to real Sepolia for on-chain |
| `SRS file missing after session reset` | Colab wipes /root on restart | SRS is cached to Google Drive — Cell 2 auto-restores it |
| `Out of memory` | Full model circuit too large | Switch to High-RAM runtime in Colab |
| `ngrok connection refused` | Token missing or invalid | Replace with your own ngrok auth token |
| `proof_5.json already exists` | Normal — Cell 3 skips re-generation | Delete `proof_5.json` if you want to regenerate |

## 🧠 Key Concepts Glossary

| Term | Meaning |
|---|---|
| **ZKML** | Zero-Knowledge Machine Learning — proving ML inference without revealing inputs |
| **ZK-SNARK** | Zero-Knowledge Succinct Non-Interactive Argument of Knowledge |
| **EZKL** | Library that converts PyTorch/ONNX models into ZK circuits |
| **ONNX** | Open Neural Network Exchange — universal ML model format |
| **KZG** | Kate-Zaverucha-Goldberg polynomial commitment scheme |
| **SRS** | Structured Reference String — trusted setup for KZG (kzg17.srs = supports 2^17 constraints) |
| **Witness** | The full trace of all intermediate values during model inference |
| **Proving Key** | Used to generate ZK proofs (private, kept by model operator) |
| **Verification Key** | Used to verify ZK proofs (public, embedded in smart contract) |
| **Sepolia** | Ethereum test network with fake ETH for safe experimentation |
| **Gas** | Computational cost unit on Ethereum — every operation has a fixed gas price |
| **Calldata** | The proof encoded as bytes for submitting to the smart contract |
| **NSL-KDD** | Network Security Lab - Knowledge Discovery and Data Mining benchmark dataset |
